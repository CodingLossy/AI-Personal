# ADR 0016 · 邮件:账户、同步、缓存与发送

- 状态:提议(M3 PR 1)
- 日期:2026-11-05
- 相关:开发计划第 7 节(安全模型)、第 8 节 M3;`docs/milestones/M3-plan.md`;ADR 0003(条目索引)、ADR 0006(密钥引用)、ADR 0007(记忆 v2)、ADR 0010(工具框架与审批)、ADR 0012(条目 API)、ADR 0015(知识库)

## 背景

M3 让助手能读邮件、总结、起草回复,并在用户确认后发送。邮件是外部的、不可信的内容,所以首要的安全目标是:邮件里写的指令不能让助手发信或做其他有副作用的事。本 ADR 定下 M3 各 PR 共用的契约;实现细节(依赖选择、迁移 0009、同步调度)在 PR 2 起各自补充到本 ADR。

## 决定

### 1. 账户配置与凭据

- 一个账户包含 IMAP(读取)与 SMTP(发送)两组服务器配置:主机、端口、加密方式(`tls` 直连 TLS,或 `starttls`),以及登录用户名与发件地址。
- **密码只保存引用**:`env:NAME` 读环境变量,`file:NAME` 读数据目录 `secrets.yaml` 中的键,规则与模型配置档的 `apiKeyRef` 相同(ADR 0006 第 2 节;`packages/shared` 的 `MailSecretRef` 复用同一正则)。API 与 Web UI 不接收明文密码;响应里只返回引用本身和 `passwordStatus`(`present` / `missing`),不返回密码。
- **不支持明文连接**:加密方式只有 `tls` 与 `starttls`,没有「不加密」(业主决定 1:只支持应用专用密码 / 授权码,不做 OAuth)。本机测试用的模拟服务器在 PR 2 中用测试证书,不为它放开明文。
- 账户只能由用户经 API / UI 增删改,没有对应的工具,模型不能修改。

### 2. 同步

- 按文件夹记录 `UIDVALIDITY` 与已同步的最大 UID;下一次只拉更大的 UID。`UIDVALIDITY` 变化时清空并重建该文件夹的缓存。
- **首次同步只拉最近 N 天**,默认 30 天,可在账户上设置(`initialSyncDays`,1–365;业主决定 2);不拉全量。
- 定时拉取为主,默认每 5 分钟(`syncIntervalMinutes`,5–1,440);IDLE 不要求(业主决定 3)。每个 owner 并发 1,失败退避重试,网络断开不影响服务运行。
- M3 只读加发送:不在服务器上改动邮件(标签、归档、删除、移动推迟,M3 方案第 6 节)。「已读」状态只在本地缓存中记录,不回写服务器。

### 3. 本地缓存

- 保存邮件头(发件人、收件人、抄送、主题、日期、`Message-ID`、`In-Reply-To`、`References`)、纯文本正文(HTML 邮件转成纯文本,不做富渲染),以及附件索引(文件名、类型、大小)。
- **附件内容只在用户要求时下载**(例如 PR 4 的「加入知识库」);不自动入库。
- 正文进入全文索引;是否进入向量检索由 PR 4 决定。

### 4. 会话串

- 优先用 `References` / `In-Reply-To`:一封邮件与它引用的邮件属于同一会话串。
- 都没有时,退回按「规范化主题 + 参与者集合」聚合:主题去掉 `Re:` / `Fwd:` / `回复:` / `转发:` 等前缀(大小写与全半角不敏感)并压缩空白,参与者为发件人与收件人地址的小写集合。
- 会话串的键(`threadKey`)由服务器计算,客户端只读。

### 5. 不可信内容

- 邮件头、正文与附件内容一律是不可信数据。交给模型时用 ADR 0010 第 7 节的 `UntrustedContent` 包装(`source.kind = 'email'`,已在契约中);邮件工具都声明 `untrustedOutput`,读过邮件之后本轮的条件预授权失效(ADR 0010 第 4 节)。
- 注入防护的策略层检查(收件人来自邮件内容时审批卡片标红)在 PR 3 中实现,判断由 core 做,不由模型做。

### 6. 发送

- `mail.send` 的风险级别为 `external`:**每次审批,不可预授权**(ADR 0010 第 3 节已规定 `external` 不能预授权)。
- 既可以发送已有草稿,也可以按参数直接发送;两种方式都要审批(业主决定 4)。审批卡片展示发件账户、收件人、抄送、主题、正文与附件名。
- 草稿(`mail.draft`,`write`)只保存在本地,不会自动发送。

### 7. 记忆

- 邮件内容不能直接成为记忆(开发计划第 7 节「记忆安全」):只能由模型提议,经用户确认后写入。这沿用 ADR 0007 第 5.5 节的规则:读过邮件的一轮,`memory.write` 一定需要审批,自动抽取的结果只进隔离区。

### 8. 契约(`packages/shared`,本 PR)

均为新增的类型,不修改已有接口:

- `MailSecretRef`、`MailSecurity`、`MailServer`。
- `MailAccount`(响应)、`MailAccountInput`(新建)、`MailAccountPatch`(部分更新)。
- `MailFolder`:账户内的文件夹,含 `uidValidity`、`lastUid`、`lastSyncedAt`。
- `MailAddress`、`MailAttachment`(只有索引)、`MailMessage`(含 `threadKey`、`inReplyTo`、`references`、`unread`、纯文本 `text`)。
- `MailThread`:会话串的摘要(主题、参与者、条数、未读数、最后一封的时间)。
- `MailDraft` / `MailDraftInput`:本地草稿,`replyToMessageId` 可选。
- `ItemSource`:列出已知的 `items.source`(`files`、`novels`、`sessions`、`memory`、`mail`)。`Item.source` 仍是字符串,以免以后新增提供者时变成破坏性修改。

REST 路径与工具的输入输出 schema 随 PR 2、PR 3 增加。

## 后果

- 账户配置与模型配置档用同一套密钥引用,运维上只有一种存放密钥的方式;代价是用户要先把授权码放进环境变量或 `secrets.yaml`。
- 只支持 TLS / STARTTLS,极少数只提供明文 IMAP 的服务器无法接入。
- 不回写服务器,用户在别的客户端看到的已读状态不会因为 AI-Personal 改变。
